\chapter{Interface tour}\label{ch:interface}

The window has a menu bar, a header, ten tabs, the assistant strip (chapter~\ref{ch:mcp}) and a bottom bar with
status, one shared progress bar, \ui{Cancel} and the map attribution, plus a line for the idle analysis
(chapter~\ref{ch:interest}). It opens 1366\,px wide (reduced to the screen if that is smaller), the width at which the
ten tab labels fit; in a narrower window the tab bar gets scroll arrows. Errors caught by the safety net appear in the status line (section~\ref{sec:robust}).

A menu entry, its button and the right-click menu (section~\ref{sec:tables}) run the \emph{same} handler. Buttons,
tabs, chips and rows are highlighted under the mouse and share one focus ring; buttons grow 5\,\% briefly (not with
\code{REVERSEHIRE\_REDUCED\_MOTION=1}).

\section{The shared progress bar}\label{sec:bar}
One bar serves every slow job: the one that started last is on top, the others reappear when it ends, and the bar
never goes backwards, even when a total grows. For the \textbf{CV} it has ten weighted steps (read, OCR, advanced
reader, sections, ESCO, translation, recruiter view, AI signals, photo, display), naming the step and, in OCR, ``page
2 of 5''. For a \textbf{search} it shows ``analysed / estimated'' companies, the estimate replaced by the final number
once ranking and the limit are known; ``about 3 min left'' appears only after three companies and 20\,s. The recruiter
analysis, job search, register download, interest flow, suggestions and downloads show ``done / estimated'' steps.
Several cards in a row have their own ``3/12'' bar in the card view.

\section{Maps}\label{sec:map}
A map appears under the place of tab 2, in Results (table $\leftrightarrow$ map) and in the job search. Points are
\emph{company}, \emph{posting}, \emph{home} and \emph{hypothesis}; a click selects the row. It is built only when first
shown (the placeholder \emph{Loading the map\ldots} appears meanwhile); about 20\,s after start-up, when you are not
typing or clicking, the web component is started in the background so that the first map opens sooner. Leaflet runs in the embedded web view (Qt WebEngine) from files that come with the program; the page is locked:
only those files, the one tile server and inline images load.

\textbf{Tiles and the OpenStreetMap policy.} By default the map asks \code{tile.openstreetmap.org} under its usage
policy: a stable User-Agent, the attribution ``\copyright\ OpenStreetMap contributors'' always visible, normal HTTP
caching (up to 200\,MB in \code{<data>/cache/map}) and \emph{only the tiles of the current view}: no prefetching.
Settings, \ui{Appearance}, offers \ui{Show the map background} (ticked by default; unticked, markers and radius are drawn on a blank background) and
a \ui{Custom tile URL} (\code{\{z\}}, \code{\{x\}}, \code{\{y\}}; \code{https}, \code{http} to this PC, or a
\code{file://} folder).

\textbf{Messages.} A panel in the centre of the map says what is wrong, with one button: background switched off
(\ui{Show the online map}); the full map could not start, or the backgrounds could not load, with the reason (no connection, a server
error, no background sent) and \ui{Retry}. A corner switch \ui{Work offline} and the \ui{Search} entries \ui{Show the
online map}, \ui{Work offline}, \ui{Retry loading the maps} do the same. If Qt WebEngine cannot start, a plain painted
map (points, radius circle, scale bar, no tiles) takes over; the log says why.

\section{About}
\ui{? $>$ About} shows the version with build and date, the credits and a table \emph{This computer} (user, computer,
system, processor, RAM, screen, graphics card, disks, network, Python, Qt, OCR engine, MCP). It is \textbf{only
shown}: never logged, saved or sent.
